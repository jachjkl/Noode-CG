# V11 链接 JP10 + 快速两级优选原理

## 1. 在线候选与去重

任务开始时，两个固定远程源各完整获取一次。链接中带 `JP` 标签的候选先进入独立通道，完成正常的严格 TCP/TLS/TTFB/下载测试并保留最好的 10 个。首轮另从 Cloudflare 官方 IPv4 CIDR 随机生成 50,000 个唯一地址；后续轮次只生成新的官方 50,000，最多 5 轮。

`data/previous-official-ips.txt.gz` 压缩保存上一任务最多 5 轮的官方样本。新任务同时排除上一任务样本、当前任务已抽取地址、固定源地址和上一轮 TOP100，避免相邻任务与同一任务重复扫描，同时避免把上百万行文本提交进仓库。

## 2. 宽松 TCPing 初筛

JP 独立通道完成后，首轮测试固定源中的非 JP 地址和官方 50,000，后续轮次测试新的官方 50,000。每个地址连续 TCP 建连三次：

```text
成功数 = 3/3
TCP 平均延迟 <= 1000ms
TCP 抖动 <= 500ms
```

按平均 TCP 延迟排序，只保留最快 5,000 个。JP 已在独立通道完成测试，不占用普通初筛名额。

## 3. 5,000 个严格三项测试

初筛 5,000 再执行三次严格 TCPing、三次 TLS 握手和三次 HTTPS TTFB：

```text
每个阶段成功数 = 3/3
严格 TCP 平均 <= 300ms
TLS 平均 <= 300ms
HTTPS TTFB 平均 <= 300ms
三项平均 <= 300ms
每项抖动 <= 500ms
```

HTTPS 必须返回可验证的 Cloudflare trace。端点国家和实际 `colo` 机房国家都必须已知且不为 `CN`。

## 4. 按需下载测速

严格合格地址按质量排序，每批下载测试 400 个，而不是像旧版本一样反复测试大批 1,000 个：

- 下载 256KiB；
- 完成率至少 95%；
- 速度至少 1Mbps；
- 每个当前地址只下载一次。

每批成功结果立即写入内存累计池。累计结果跨官方轮次保留；普通合格地址与链接 JP10 合计达到 TOP200 后立即停止，当前地址不再进入额外最终复测。

## 5. 上一轮 TOP100

上一轮 TOP100 中的非 JP 地址使用新对象单独执行一次严格 TCPing、TLS、TTFB 和下载测试。JP10 每次都从本轮两个在线链接重新选择。通过者与本轮累计池共同排名，同一地址不会重复测速。

## 6. 发布门槛

最终排序顺序为：

```text
丢包率升序 → 下载速度降序 → 三项平均延迟升序 → 最大抖动升序
```

只有同时满足以下条件才覆盖订阅：

```text
至少完成一批 5,000 个初筛候选
唯一 IP 总数 >= 200
日本端点 >= 10
GitHub Runner 的 Google / Cloudflare / GitHub 基线正常
```

不满足时保留最近一次非空合格订阅；首次部署尚无旧订阅时保持为空。
