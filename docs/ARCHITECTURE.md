# V10 快速两级优选原理

## 1. 在线候选与去重

任务开始时，两个固定远程源各完整获取一次。首轮另从 Cloudflare 官方 IPv4 CIDR 随机生成 50,000 个唯一地址；后续轮次只生成新的官方 50,000。

`data/previous-official-ips.txt` 保存上一任务的官方样本。新任务同时排除上一任务样本、当前任务已抽取地址、固定源地址和上一轮 TOP100，避免相邻任务与同一任务重复扫描。

## 2. 宽松 TCPing 初筛

首轮测试固定源全量地址和官方 50,000，后续轮次测试新的官方 50,000。每个地址连续 TCP 建连三次：

```text
成功数 = 3/3
TCP 平均延迟 <= 1000ms
TCP 抖动 <= 500ms
```

按平均 TCP 延迟排序，只保留最快 5,000 个。为了满足最终 JP10，初筛会优先保留一定数量带 `JP` 来源标签的候选。

## 3. 5,000 个严格三项测试

初筛 5,000 再执行三次严格 TCPing、三次 TLS 握手和三次 HTTPS TTFB：

```text
每个阶段成功数 = 3/3
严格 TCP 平均 <= 300ms
TLS 平均 <= 300ms
HTTPS TTFB 平均 <= 300ms
三项平均 <= 300ms
每项抖动 <= 500ms
```

HTTPS 必须返回可验证的 Cloudflare trace。端点国家和实际 `colo` 机房国家都必须已知且不为 `CN`。

## 4. 按需下载测速

严格合格地址按质量排序，每批下载测试 400 个，而不是像旧版本一样反复测试大批 1,000 个：

- 下载 256KiB；
- 完成率至少 95%；
- 速度至少 1Mbps；
- 每个当前地址只下载一次。

每批成功结果立即写入内存累计池。累计结果跨官方轮次保留；达到 TOP200 和 JP10 后立即停止，当前地址不再进入额外最终复测。

## 5. 上一轮 TOP100

上一轮 TOP100 使用新对象单独执行一次严格 TCPing、TLS、TTFB 和下载测试。通过者与本轮累计池共同排名。上一轮地址从本轮固定源与官方候选通道排除，因此同一任务中也只测试一次。

## 6. 发布门槛

最终排序顺序为：

```text
丢包率升序 → 下载速度降序 → 三项平均延迟升序 → 最大抖动升序
```

只有同时满足以下条件才覆盖订阅：

```text
至少完成一批 5,000 个初筛候选
唯一 IP 总数 >= 200
日本端点 >= 10
GitHub Runner 的 Google / Cloudflare / GitHub 基线正常
```

不满足时保留最近一次非空合格订阅；首次部署尚无旧订阅时保持为空。
